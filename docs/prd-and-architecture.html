Problem Space

Diagnosing the Current Failures & The Anti-Regression Standard

✕

The "Scroll-to-Finish" Illusion

In lib/pedagogy.ts, 7 chunk types were marked as SCROLL_COMPLETE_TYPES. Users reached within 80px of the bottom, and the app automatically marked the lesson completed. Zero active production. Zero learning.

✕

The "Fake Flashcard" Memorization

In VocabularyView.tsx, tapping through the cards once marked the entire vocabulary list as mastered. No active recall challenge, no error retry queue, and no spaced repetition. 70% of vocabulary is forgotten within 24 hours.

✕

Cognitive Bombardment & Passive Blocks

The pedagogy lab became clogged with 18+ verbose widgets dumping multi-sentence tables, bilingual grammar rules, and linguistic meta-jargon. The user is overwhelmed with multiple things to read instead of one playful thing to solve.

The Non-Negotiable Law Core Pedagogical Contract

The Principle of Cognitive Singularity

Every screen in a lesson MUST present exactly ONE cognitive challenge. The user must never worry about grammar rules, vocabulary definitions, and translation all at once. They see a single clear visual cue or prompt, formulate an answer in their mind, execute a tactile physical action (tap, assemble, swipe), and receive instant sensory feedback.

Core Architecture

The 4 Interlocking Pillars of the Application

Pillar I

Playful Interactive Session Runner

Replaces disconnected chunk router hops with a continuous, focused flow. Each lesson is a sequence of micro-challenges running inside a unified viewport.

  • ✓ No Scroll Completion: Every step requires active tactile input to advance.
  • ✓ In-Session Error Queue: Wrong answers are re-queued at the end of the lesson until cleared 100%.
  • ✓ Fisher-Yates Shuffling: Word chips are always randomized with anti-identity checks.
  • ✓ 56px Touch Standards: Design system compliant tactile primary action footer.
Component: apps/web/src/components/runner/LessonSessionRunner.tsx
Pillar II

Item-Level Retention Engine (SRS)

Upgrades the binary "completed" string in progressStore to a scientifically grounded spaced repetition system tracking every word, phrase, and grammar pattern.

  • ✓ Granular Tracking: Tracks vocab:id, phrase:id, and pattern:id.
  • ✓ Memory Decay & Intervals: Calculates next review dates (1d, 3d, 7d, 16d, 35d).
  • ✓ Dynamic Lesson Rings: Completed lessons decay when items are due, triggering review badges.
  • ✓ 90s Daily Spaced Review: Instant rapid-fire queue of items needing refresh.
Store: apps/web/src/state/retentionStore.ts
Pillar III

Lexical Vault & Words Analysis Page

A dedicated mastery dashboard where learners inspect their entire vocabulary repertoire, trilateral root networks, and Quranic frequency distributions.

  • ✓ Vocabulary Inventory: Filter by volume, chapter, root, or mastery level.
  • ✓ Root Morphology Inspector: Explore words derived from the same trilateral root (e.g. ك-ت-ب).
  • ✓ Quran Frequency Badges: Shows how many times each learned word occurs in the Mushaf.
  • ✓ Audio & Harakat Player: Crisp pronunciation clips and morphological breakdown.
Route: apps/web/src/routes/words/index.tsx
Pillar IV

Real-Time Quran Mushaf Illumination

The crown-jewel feature. Every word and grammar pattern mastered in the curriculum is dynamically mapped onto the 604 pages of the King Fahd QCF v2 digital Mushaf.

  • ✓ Uthmani Word Matching: Exact token normalization matching curriculum lemmas to Quranic tokens.
  • ✓ Visual Illumination: Mastered words glow softly in gold/emerald; unknown words stay neutral.
  • ✓ Surah & Page Comprehension %: "You now understand 42% of Surah Al-Baqarah".
  • ✓ Tap-to-Inspect Quran Word: Shows lemma, translation, and links to the lesson where it was learned.
Route: apps/web/src/routes/mushaf-v2/index.tsx

Memory Science

Item-Level Retention Engine & Spaced Repetition (SRS)

The Active Recall & Mistake Recycling Loop

Step 1
Priming
Audio + Glyph + Meaning. Single glance.
Step 2
Production
Assemble or select in under 5 seconds.
Step 3
Error Queue
Wrong answer? Added to recycle queue immediately.
Step 4
End-of-Session Recovery
Must clear 100% of error queue to pass.
Step 5
SRS Interval
Interval scheduled: Day 1 → 3 → 7 → 16 → 35.
ItemRetention Data Model (packages/shared/src/types/retention.ts)
export interface ItemRetention {
  itemId: string;             // e.g., "vocab:v1_c1_kitab", "pattern:haza_ism"
  itemType: 'word' | 'phrase' | 'grammar_pattern';
  arabic: string;               // Full Tashkeel Arabic
  lemma: string;                // Normalized base form for Quran token matching
  meaningEn: string;
  meaningBn: string;
  volume: number; chapter: number; lesson: number;

  // Spaced Repetition State
  box: number;                  // 0: New, 1: Learning, 2: Familiar, 3: Proficient, 4: Mastered
  consecutiveCorrect: number;   // Active streak
  totalAttempts: number;
  totalErrors: number;
  lastPracticedAt: number;      // Unix timestamp (ms)
  nextReviewDue: number;        // Unix timestamp (ms)
  stability: number;            // Memory half-life in days
}

export interface LessonSessionSummary {
  volumeId: number; chapterId: number; lessonNum: number;
  accuracyRate: number;         // e.g. 94.2%
  firstTryCorrectCount: number;
  recycledErrorsResolved: number;
  durationSeconds: number;
  newWordsLearned: string[];
  wordsReinforced: string[];
  quranicEchoUnlocked?: {
    surahNumber: number; ayahNumber: number;
    arabicText: string; translation: string;
  };
}
