Java Lab Integration

Three architectural proposals for incorporating Spring Boot into the Tariq App

Option 1 (Recommended)

The "Progress & Analytics" Microservice

In this model, the TanStack Start app continues to handle the UI and static curriculum data, but the Spring Boot app acts as a dedicated backend for tracking user progress, test scores, XP, and analytics. 

                            graph TD
                            A[TanStack Start Frontend] -->|UI & Local Data| A
                            A -->|POST /api/progress| B(Spring Boot Backend)
                            A -->|GET /api/leaderboard| B
                            B --> C[(PostgreSQL DB)]
Pros:
  • Clean separation of concerns.
  • TanStack Start remains fast for static curriculum content.
  • Fulfills lab requirements perfectly with clear REST APIs and DB integration.
  • Easy to document (Swagger/OpenAPI).
Cons:
  • Requires maintaining two separate deployment environments (Node.js + Java).
  • Need to handle CORS and JWT authentication between the two.
Option 2

The Full Headless CMS

Instead of hardcoding curriculum data (like lesson payloads) in TypeScript, we move ALL curriculum content into a relational database managed by Spring Boot. The frontend simply fetches lesson JSON payloads from the Spring Boot API. 

                            graph TD
                            A[TanStack Start SSR] -->|Fetch /api/lessons/:id| B(Spring Boot Backend)
                            B --> C[(PostgreSQL DB)]
                            A -->|Renders HTML| D[User Browser]
Pros:
  • Very impressive for a university lab project.
  • Allows curriculum updates without recompiling the web app.
  • TanStack Start's SSR works beautifully with external APIs.
Cons:
  • Massive data entry overhead (migrating all TypeScript objects to SQL).
  • Latency issues if the Spring Boot server isn't fast enough.
Option 3

The Gateway / BFF Pattern

Spring Boot acts as the main entry point (Gateway) for the application. It handles authentication and session management. It serves the frontend assets (or proxies requests to TanStack Start) and handles its own business logic. 

                            graph TD
                            User -->|Requests| B(Spring Boot Gateway)
                            B -->|Proxy UI Routes| A[TanStack Start]
                            B -->|Handle Data Routes| C[(Database)]
Pros:
  • Avoids CORS issues entirely (same origin).
  • Spring Security can handle all authentication easily.
Cons:
  • Complex routing setup.
  • Might fight against TanStack Start's built-in full-stack capabilities.
