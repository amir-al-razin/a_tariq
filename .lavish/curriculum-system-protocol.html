1. The Five Pillars of Parallel Agent Execution

How autonomous agents operate independently across different tabs with guaranteed fidelity and zero quota waste.

Pillar 1: UI Gating

Lavish Gate for New Components

If a textbook section directly fits existing pedagogy components (VocabGrid, PointerDrillList, InteractiveDrill), reusing them is strictly mandatory.

The Exception Gate: When a textbook section genuinely requires a brand-new UI structure, the agent must NOT invent it randomly. Instead, the agent must immediately invoke Lavish, render a visual mock of the proposed component, and halt execution to call for Captain intervention and visual verification.

Pillar 2: Exhaustive Coverage

100% Content Coverage

Every single vocabulary word, practice pair, sentence, and exercise printed on the assigned textbook pages must be implemented in full.

Implementing partial snippets (5% or 10% of a lesson) is banned. Each individual line in the book must map directly to a specific pedagogical presentation step.

Pillar 3: Data Strategy

English UI + Bangla Background Data

To keep the immediate learning curve clean while preparing for future internationalized features (Inshallah), all visible UI translations will render exclusively in English for now.

However, every data object generated by agents must simultaneously include the Bangla translation in the underlying record (e.g., en: 'A book', bn: 'একটি বই'), ensuring seamless multi-language activation later.

Pillar 4: Zero Overwhelm

No Unstated Grammar Bloat

Implement strictly what is stated in the physical book. Do not invent words that are not printed.

No Linguistic Bloat: Never add overwhelming linguistic metadata, grammar titles, sentence type labels, or academic explanations that do not exist in the book's text. If the book presents simple Arabic sentences, show the Arabic sentences and their meaning—nothing extra.

Pillar 5: Design System Strictness

Absolute Design System & Theme Compliance

Whenever reusing existing UI or proposing brand-new components through Lavish, agents must strictly abide by our established design system, colors, and theme. Agents are forbidden from injecting independent stylistic assumptions or inventing ad-hoc visual rules. All UI elements must faithfully mirror the existing design tokens and theme structure of our application.

3. Established Pedagogy Component Matrix

Parallel agents must categorize textbook content into these existing components first. If content fails to fit, the agent must initiate a Lavish verification poll.

Component Name Textbook Content Type Visual Implementation Rule Strict Prohibition
VocabGrid Vocabulary word lists introduced at the beginning of sections. Shows Arabic word, English meaning, tap-to-reveal Romanization, and card numbers. Emojis ONLY if illustrated in book. Do not force random icons onto abstract adjectives or grammatical particles.
PointerDrillList Demonstrative pointing exercises (Hatha, Thalika, etc.) and directional sentences. Displays Arabic sentence with spatial badge (NEAR/FAR) and optional matching icon if drawn in book. Never use for normal reading paragraphs or dialogues that do not involve physical pointing.
InteractiveDrill Active student work: Q&A answering, translation exercises, and fill-in-the-blank drills. Interactive word-chip selection or blank fill where the student builds the expected sequence. Do not turn passive reading examples into mandatory puzzles unless marked as practice work.
Pure Canvas / Table Simple side-by-side phrase pairs or grammar examples without practice prompts. Clean, well-spaced typographic cards adhering strictly to our design system and theme colors. Do not add overwhelming linguistic metadata or theoretical grammar titles not present in the text.
NEW COMPONENT NEEDED? Content that genuinely cannot fit into the existing pedagogical components above. AGENT MUST STOP CODING & LAUNCH LAVISH TO ASK FOR CAPTAIN INTERVENTION. NEVER invent or push unverified UI components into pedagogy-v2/ autonomously.

4. Parallel Agent System Prompt Instructions

When we spin up subagents across tabs for future lessons, every agent will be fed this non-negotiable instruction block.

### PARALLEL AGENT CURRICULUM DEVELOPMENT INSTRUCTIONS (BEDROCK RULES) ###
1. EXHAUSTIVE CONTENT COVERAGE: You must implement 100% of the vocabulary, sentences, and exercises
   from your assigned Esho Arbi Shikhi textbook pages. Do NOT abbreviate or implement only 5-10% of the lesson.
2. STRICT UI vs DATA LANGUAGE BOUNDARY:
   - Visible UI Translations: MUST BE ENGLISH ONLY (matching Lesson 1 & 2).
   - Background Data Records: ALWAYS include Bangla translation in the data object (e.g., { en: 'A book', bn: 'একটি বই' })
     to prepare our foundation for future multi-language capabilities.
3. ZERO UNNECESSARY GRAMMAR OVERWHELM & STRICT BOOK FIDELITY:
   - Implement ONLY what is printed in the book. Do not invent sentences or extra vocabulary.
   - DO NOT add overwhelming theoretical grammar titles, sentence type tags, or academic explanations
     that are not explicitly printed in the book. Keep it clean and simple.
   - Emojis/Icons are ONLY allowed when the book has physical illustrations (e.g. pointing drills).
4. MANDATORY COMPONENT REUSE & LAVISH GATING:
   - Re-use existing pedagogical components (VocabGrid, PointerDrillList, InteractiveDrill) by default.
   - IF AND ONLY IF a section cannot fit into these components, YOU MUST NOT CREATE A NEW COMPONENT SILENTLY.
     Instead, launch a Lavish visual mock of your proposed component and poll for Captain approval first!
5. ABSOLUTE DESIGN SYSTEM & THEME COMPLIANCE:
   - All component structures must strictly obey our established design system, colors, and theme.
   - Do not inject independent stylistic assumptions or invent ad-hoc visual rules.
   - Zero Box Shadows: shadow-* CSS utilities are strictly illegal in our Raw Neutral design system.
   - No Inline Theme Toggles: Do not add local theme toggles or isDark state inside lesson components (controlled globally in navbar).
6. STEP SEQUENCING & PEDAGOGICAL SEPARATION:
   - Vocabulary Precedes Content: New vocabulary listed at the bottom of a textbook page MUST appear in a standalone vocabulary step BEFORE any reading or practice exercises of that page begin.
   - Separate Examples from Practice: Never mix translated demonstrations (Familiarization) and non-translated student exercises (Practice) within the same step!
   - No Static Translations for Exercises: When textbook practice sentences lack translations, put them directly into interactive exercises where the learner actively reconstructs the meaning.
7. INTERACTIVE DRILLS & RESPONSIVE UI MECHANICS:
   - Word Chip Shuffling: Always use an unbiased Fisher-Yates shuffle memoized via useMemo with anti-identity checks so word chips never render in static answer order.
   - Responsive Layouts: Rely on CurriculumHeader and CurriculumFooter from shared components with Arabic numeral badge boxes (١, ٢, ٣...) and responsive flex wrapping.

Foundation Locked & Active

Protocol V2 is finalized, all independent stylistic assumptions are purged, design system alignment is mandated, and we will continuously track and evolve this foundation if new textbook requirements arise.
